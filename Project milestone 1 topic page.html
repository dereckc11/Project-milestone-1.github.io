Subtopic 1: The Evolution of Concurrency Models

The defining architectural characteristic of any web server platform is its **concurrency model**—the method it implements to juggle multiple clients connecting over network cords simultaneously.

Traditional Process-Per-Connection Models

Early systems, such as the legacy deployment modes of the Apache HTTP Server, spawned a completely separate operating system process or thread runtime environment for every single connecting user. While this design provides strict process fault isolation, it creates severe processing limits under heavy loads. Because processes preserve individual isolated RAM memory heaps, spawning thousands of users causes severe CPU thrashing due to endless operating system context switching.

Modern Event-Driven Asynchronous Loops

Modern servers, such as Nginx, avoid these structural bottlenecks by leveraging a non-blocking architecture. A single master background thread initializes an infinite execution circle called an Event Loop. Instead of idling while waiting for a solid-state drive or network stack to respond, the engine records the connection context within native operating system multiplexing engines like epoll and immediately services subsequent actions, keeping performance fast and lightweight.
